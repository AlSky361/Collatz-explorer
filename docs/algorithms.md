# Алгоритм и измерения

Семантика метрик и форматы заданы в [справочнике](api.md).
Оптимизации сохраняют обычные шаги Коллатца и учёт всех значений цепочки.

## Структура

| Каталог | Ответственность |
|---|---|
| `include/collatz/` | Публичные `collatz_core.hpp`, `summary.hpp`, `range_executor.hpp` |
| `src/core/` | Цепочки, мемоизация, сводки и рабочие потоки |
| `src/internal/` | Подсчёт цифр и внутренний доступ к неизменяемому кэшу |
| `src/app/` | CLI, конфигурация, экспорт в `exporters.*`, публикация наборов и паспорт |
| `python/visuals/` | Выбор набора, загрузка данных, графики и модели |
| `tests/cpp/`, `tests/python/` | Модульные, сквозные и визуальные проверки |
| `benchmarks/` | Сравнение бинарников, профилирование и сырые замеры |
| `examples/`, `cmake/`, `third_party/` | Конфигурации, модули сборки, закреплённая JSON-библиотека |

CMake-цель `collatz_core` предоставляет `include/`; публичные заголовки
не зависят от `src/` и JSON-парсера. Метаданные сборки паспорта генерирует CMake.
`build/` содержит локальные артефакты и не нужен в исходниках.

В Python `result_paths.py` выбирает готовый набор, `data_source.py` читает
CSV/JSON и кэширует загруженные столбцы и суммы первых цифр. `plot_ui.py`
создаёт окна и элементы управления; `plot_cli.py` обрабатывает аргументы
отдельных статистических графиков. Функции построения возвращают `Figure`,
по умолчанию без вызова `plt.show()`.

## Вычисления и память

- Первые цифры: битовые операции для оснований — степеней двойки,
  целочисленные таблицы и деление для остальных оснований.
- Кэш хранит только нечётные значения до `memo_capacity` в отдельных массивах
  полей (SoA). Для `[2,8,10,16]` — 74 байта на запись, при границе 100000
  массивы занимают 3 700 000 байт. Чётные запросы дают промах; нулевые частоты,
  двоичные цифры и число чётных шагов восстанавливаются при чтении.
- Кэш заранее заполняется одним потоком, затем публикуется как неизменяемый
  через release/acquire. Чтения не берут мьютекс; изменяемый API защищён им.
- Постоянные `std::jthread` переиспользуют буферы. Без CSV они накапливают
  собственные сводки; работа выдаётся порциями до 4096 элементов.
- CSV использует два блока: запись готового перекрывается с вычислением
  следующего. Строки сохраняются по порядку. Форматирование — `std::to_chars`
  и таблица десятичных записей 0…999 для малых счётчиков.

Без CSV кэшированные хвосты можно учитывать отложенно: префиксы сразу
добавляются в счётчики, хвосты — один раз с накопленными целочисленными весами.
Массивы весов на каждый поток включены в оценку памяти; на малых диапазонах
и для одного основания 2 используется обычный путь. Последовательные деления
на 2 объединяются через `std::countr_zero`, но цифры каждого значения учитываются.

В полном диапазоне 1…N старты группируются в семейства `m*2^j`, m нечётно.
При `K=floor(log2(N/m))` общий хвост m учитывается K+1 раз:

```text
length(m*2^j) = length(m) + j
odd_steps(m*2^j) = odd_steps(m)
even_steps(m*2^j) = even_steps(m) + j
max_value(m*2^j) = max(max_value(m), m*2^j),  j=0…K
```

Префиксное значение `m*2^i` добавляется K−i+1 раз. Например, для стартов
3, 6, 12, 24 цепочка 3 учитывается четырежды, значения 6, 12, 24 — три, два
и один раз. Этот путь применяется без CSV при активных отложенных хвостах;
произвольные срезы считаются независимо. Лимит шагов проверяется и для
самого длинного члена семейства.

## Производительность

Текущая серия: macOS arm64, Apple Clang 21, Python 3.14.5, Release с LTO.
Миллион стартов, 4 потока, `[2,8,10,16]`, кэш 100000, блок 10000,
100 интервалов; медианы семи чередующихся запусков.

| Режим | До паспорта и наборов | Текущая версия | Пиковый RSS текущей версии |
|---|---:|---:|---:|
| Только сводка | 0.0401 с | 0.0418 с | 7.47 MiB |
| CSV и сводка | 0.1825 с | 0.1951 с | 8.06 MiB |

Время измерено снаружи процесса, включая запуск, расчёт и закрытие файлов.
Сборка, графики и принудительный сброс на накопитель исключены. RSS относится
к приложению без Python-обёртки. Фоновая нагрузка и файловый кэш не изолированы;
разницу нельзя считать отдельным измерением стоимости публикации.
CSV и сводка совпали побайтно между версиями и во всех повторениях;
паспорт с переменными временами исключён из сравнения.

Актуальные [исходные измерения](../benchmarks/output-publication.json) содержат
параметры, отдельные повторы и SHA-256 исполняемых файлов. Пути бинарников
записаны относительно проекта; для внешних файлов сохранены только имена.

Сравнение любых двух готовых бинарников на macOS/Linux:

```bash
python3 benchmarks/compare.py /path/to/before /path/to/after --output build/comparison.json --repeats 7 --cases four_threads csv
```

Скрипт использует временный каталог и проверяет совпадение данных.
Для профилирования соберите цель `collatz_profile`, затем вызовите
`python3 benchmarks/profile.py /path/to/before_profile /path/to/after_profile --output build/profile.json`.
Профайлер разделяет стадии CSV последовательным диагностическим проходом;
его времена не равны времени рабочего конвейера и не складываются со сводкой.
