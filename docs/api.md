# Запуск, параметры и данные

[README](../README.md) содержит первый пример. Здесь описаны интерфейс CLI,
конфигурация, результаты и выбор данных для графиков.

## Запуск

```bash
./build/release/collatz_run config.json output
```

Аргументы позиционные: JSON-конфигурация и выходной каталог. Без аргументов
используются `config.json` и текущий каталог; относительные пути отсчитываются
от текущего каталога. Скрипты сборки задают свои пути по умолчанию — см.
[сборку](development.md#build).

## Конфигурация

| Параметр | По умолчанию / диапазон | Назначение |
|---|---|---|
| `n_max` | Обязателен; 1…10¹² | Старты от 1 до N включительно |
| `bases` | Обязателен; уникальные целые 2…36 | Непустой список оснований |
| `batch_size` | 10000; 1…10⁷ | Число строк блока CSV; без CSV не используется |
| `memo_capacity` | 100000; ограничивается `n_max` | Верхняя граница кэшируемых значений; 0 отключает кэш |
| `threads` | 0; явно 1…256 | 0 = авто, не более 32; фактическое число ограничивается объёмом работы |
| `memory_budget_mb` | 256; 16…1048576 MiB | Бюджет оценки рабочих данных перед выделением памяти |
| `write_csv` | `true` | Подробные результаты для каждого старта |
| `summary_bins` | 100; 0…10000 | Число интервалов сводки; 0 отключает её |
| `coral_n_count` | 0; 0…10000 | Траектории стартов 1…count |
| `coral_n_list` | `[]`; до 10000 элементов | Дополнительные положительные `uint64_t` |

Неизвестные ключи, дробные/логические значения вместо целых и повторные
основания отклоняются. Хотя бы один выход — CSV или сводка — обязателен.
Для большого N обычно достаточно `write_csv=false`: статистические графики
строятся по сводке. Оценка памяти учитывает кэш, блоки, основания и потоки,
но не ограничивает RSS процесса, стеки и расходы рантайма.
Готовые конфигурации: [10000 стартов](../examples/quickstart.json),
[миллион стартов](../config.json).

## Метрики и файлы

Чётный шаг — `n/2`, нечётный — `3n+1`. Остановка при первом достижении 1;
для старта 1 длина равна 0. Числа хранятся в `uint64_t`, счётчики сводки —
в 64-битных целых. Проверки переполнения и предела 60000 шагов действуют
и в Release; ошибка расчёта или записи возвращает код 1.

| Файл | Содержимое |
|---|---|
| `collatz_results.csv` | `n,length,max_value,odd_steps,even_steps` и `fd_b{base}_d{digit}` |
| `collatz_summary.json` | Сводка версии 2: гистограммы, `length_counts`, суммарные первые цифры, N и основания |
| `collatz_coral.csv` | `n,step,value` для объединения count и list без повторных стартов |
| `run_info.json` | Паспорт версии 1: параметры, сборка, потоки, времена и список файлов |

Первые цифры учитывают **каждое значение полной траектории**, включая старт
и завершающую 1. Для `n=3` это `3 → 10 → 5 → 16 → 8 → 4 → 2 → 1`.
Сумма частот одного основания в строке равна `length + 1`, частота цифры 0 — 0.
Общие хвосты разных цепочек считаются повторно: наблюдения — появления значений,
а не уникальные достигнутые числа.

В сводке интервалы `length`, `odd_steps`, `even_steps` линейные по наблюдаемому
диапазону, а `max_value` — фиксированные логарифмические по `[1, 2^64]`.
`edges` заданы в исходных единицах; интервалы включены слева, последний включает
правую границу. Частоты длин и первых цифр точные. Сводки старой версии
отклоняются; старые данные без учёта промежуточных `3n+1` нужно пересоздать.

## Наборы результатов и паспорт

Успешный запуск создаёт `output/collatz_runs/run-<время>-<идентификатор>/`
с паспортом и только включёнными экспортами. Данные сначала пишутся
в `.pending-run-…`; после закрытия файлов папка публикуется одним
переименованием внутри `collatz_runs/`. Прежние наборы сохраняются,
параллельные процессы создают отдельные папки. Сообщение об успехе
появляется после публикации; принудительный `fsync` не используется.

При исключении удаляется по возможности только служебная папка этого запуска.
После аварийного завершения оставшиеся `.pending-run-…` игнорируются;
их можно удалить вручную после остановки расчёта. Каждый сохранённый CSV
занимает место отдельно; автоматической очистки старых наборов нет.

| Поле паспорта | Значение |
|---|---|
| `schema_version`, `status`, `run_id` | 1, `complete`, идентификатор набора |
| `started_at_utc`, `finished_at_utc` | UTC с суффиксом `Z`; завершение фиксируется при подготовке паспорта |
| `program`, `build` | Версия из CMake, C++20, конфигурация, ОС, архитектура и компилятор |
| `config` | Параметры с применёнными умолчаниями и ограничением кэша по N |
| `execution` | `threads_used`, `hardware_threads`, `estimated_working_bytes` |
| `timing` | `elapsed_seconds` до закрытых файлов данных и описание границ измерения |
| `files` | Имена и размеры файлов данных после закрытия; без самого паспорта |

`config.threads` хранит запрос, включая 0; `execution.threads_used` — фактическое
число потоков. Например, при CSV и `batch_size=1` используется один поток.
Время паспорта исключает его создание и публикацию; консольное `Processed …`
включает эти операции. Версии паспорта и сводки независимы.

## Графики

После установки зависимостей активируйте окружение или вызывайте его Python
напрямую, как в [README](../README.md). Общая галерея:

```bash
python python/visuals/demo.py --input-dir output
python python/visuals/demo.py --input-dir output --save-dir output/figures --no-show
```

Отдельный график: `python python/visuals/benford_digits.py output`.

При импорте `build_figure(..., show=False)` возвращает `matplotlib.figure.Figure`;
окно показывается только при `show=True` или отдельном `plt.show()`.
`data_source.open_data_source(path)` закрепляет CSV/JSON для повторного
использования; загрузка данных не зависит от аргументов командной строки.

| Скрипт в `python/visuals/` | График |
|---|---|
| `chain_length_hist.py` | Гистограмма длин |
| `chain_length_distribution.py` | Нормированная гистограмма и выборочная функция распределения длин |
| `odd_even_steps_hist.py` | Чётные и нечётные шаги |
| `max_value_hist.py` | Гистограмма максимумов и выборочная функция распределения |
| `benford_digits.py` | Первые цифры и ориентир Бенфорда |
| `coral_trajectories.py` | Coral-траектории |

Статистические графики читают сводку без CSV. Длины по X и шаги по обеим
осям линейные; максимумы используют логарифмическую X и относительные частоты.
Доступны переключатели нормировки, основания и масштаба Y для длин.
Интервалы сводки заданы при расчёте; выборочная функция распределения длин
точная. Для максимумов JSON показывает приближение выборочной функции
распределения по сгруппированным данным: точные скачки внутри интервалов
восстановить по сводке нельзя.

Явный `.csv` включает подробный режим с подбором интервалов и моделей;
память растёт с размером выборки. Подгонка по тем же данным не подтверждает
теорию независимо; в режиме сводки она не выполняется.

Правила выбора данных:

- Каталог `output` выбирает готовый набор по максимальному `finished_at_utc`,
  затем `run_id`. Галерея закрепляет один набор для всех графиков.
- Папка конкретного запуска закрепляет эксперимент; её можно перенести целиком.
  Существующий явный CSV/JSON читается как есть и не заменяется более свежим.
- Проверяются паспорт, имена, наличие и размеры файлов. Повреждения вызывают
  ошибку; содержимое целиком не хешируется. Отключённые выходы не берутся из
  других запусков. Явные `.pending-run-…` отклоняются.
- Без новых наборов поддерживаются прежние файлы в переданном каталоге;
  сводка предпочитается, если не старее CSV. Без аргумента отдельные скрипты
  ищут результаты в корне проекта.

## Обозначения на графиках

Используется соглашение лекций 4 (§ 4.1), 6 (§ 6.3) и 12 (§ 12.2):
`F_X(x)=P{X<x}`, `F_X^*(x)=#{x_k<x}/N`, `f_X(x)` — плотность непрерывной
модели. Выборочная функция распределения непрерывна слева: в точке скачка
учитываются только строго меньшие значения. Функция показана ступенчатой линией
без отдельных маркеров в точках скачков.

`N` — объём набора наблюдений, `n_i` — частота значения или интервала,
`n_i/N` — относительная частота. Для гистограммы с шириной интервала `h_i`
нормированная высота равна `n_i/(N*h_i)`, так что сумма площадей равна 1.
Длины и шаги дискретны: нормированная гистограмма не называется их истинной
плотностью. На графике Бенфорда `N` считает появления значений во всех цепочках,
`n_d/N` — наблюдаемая частота цифры, `p_d=log_b(1+1/d)` — ориентир модели.
Столбцы Бенфорда образуют гистограмму относительных частот; линия через
наблюдаемые частоты — полигон относительных частот.

Для статистики максимумов `T_j(k)` — значение после j обычных шагов Коллатца
от старта k: `T_0(k)=k`, затем деление на 2 для чётного значения или `3x+1`
для нечётного. Наблюдения `x_k=max_j T_j(k)` берутся до первой 1 включительно;
для длин `x_k=L(k)`. Частота интервала определяется суммой индикаторов
`n_i=sum_k 1_{Delta_i}(x_k)`, а функция распределения —
`F_X^*(x)=(1/N)*sum_k 1_{x_k<x}`. Индикатор равен 1 при выполнении условия и 0 иначе.

Все статистические графики используют общую синюю палитру и сетку основных
делений; кривые различаются оттенком и типом линии. Градиент траекторий сохраняется.

Нормальный закон записывается как `N(m, sigma)` со среднеквадратическим
отклонением во втором параметре. В эвристической модели длин
`m_X(n)=C*ln(n)+b`, `D_X(n)=sigma2*ln(n)`, `sigma_X(n)=sqrt(sigma2*ln(n))`.
Перебор стартов и связанные появления в цепочках не являются независимой
случайной выборкой; графики описывают вычисленный набор и не выполняют
статистическую проверку закона распределения.
